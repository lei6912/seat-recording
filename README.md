# 座號錄音繳交系統

學生**不需要帳號密碼、不需要複製貼上任何網址**：
選自己的座號 → 按一下麥克風錄音 → 送出，就完成繳交。

老師在後台一眼看出**哪些座號還沒交**，並且可以**直接播放**每個人的錄音、下載存檔。

錄音檔存在**老師自己的 Google 雲端硬碟**，繳交紀錄寫在**老師自己的 Google 試算表**。
網頁本身是純靜態的，放在 GitHub Pages 上即可。

| 頁面 | 網址 | 給誰用 |
|---|---|---|
| 學生繳交 | `https://<你的帳號>.github.io/<repo 名稱>/` | 學生（網址發給全班） |
| 教師後台 | `https://<你的帳號>.github.io/<repo 名稱>/admin.html` | 老師（帳號 `imp5477` / 密碼 `imp5477`） |

---

## 一、學生那邊看到什麼

1. 點自己的座號（1～21）。
2. 按一下圓形的麥克風按鈕 → 瀏覽器問要不要用麥克風 → 選「允許」。
3. 開始講，講完再按一下同一個按鈕停止。
4. 出現播放器可以先試聽；不滿意按「重新錄音」。
5. 按「送出繳交」。完成。

只有兩步，沒有要貼網址、沒有要裝 App。
同一個座號再錄一次送出就會覆蓋舊的，所以交錯了可以直接重交。

## 二、設定（必要，約 3 分鐘）

GitHub Pages 只能放靜態網頁，**沒有伺服器、也不能存檔案**，
所以錄音檔必須存到別的地方——這裡用老師自己的 Google 帳號，免費且永久。

**設定完成前，系統會停在「本機測試模式」：錄音只存在那一台裝置，老師後台看不到。**

### 步驟 1：建立試算表與程式

1. 到 [sheets.new](https://sheets.new) 開一個新的 Google 試算表（檔名隨意，例如「錄音繳交」）。
2. 上方選單 **擴充功能 → Apps Script**。
3. 把編輯器裡原本的 `function myFunction() {}` 全部刪掉。
4. 打開本專案的 [`apps-script/Code.gs`](apps-script/Code.gs)，把**整個檔案的內容**複製貼進去。
5. 按存檔（💾）。

### 步驟 2：部署成網頁應用程式

1. 右上角 **部署 → 新增部署作業**。
2. 左邊齒輪 ⚙ **選取類型 → 網頁應用程式**。
3. 設定：
   - **執行身分**：`我`
   - **誰可以存取**：`所有人` ← **這項一定要選對**，不然學生交不出來
4. 按 **部署**。第一次會要求授權：選你的 Google 帳號 →
   出現「Google 尚未驗證這個應用程式」時，點 **進階 → 前往「專案名稱」(不安全)** → **允許**。
   （這是你自己寫給自己用的程式，所以 Google 不認識它，屬正常現象。
   它要求雲端硬碟權限，是因為要幫你把學生的錄音檔存進你的硬碟。）
5. 複製畫面上的 **網頁應用程式網址**，長得像：
   ```
   https://script.google.com/macros/s/AKfycbxxxxxxxxxxxxxxxxxxxx/exec
   ```

### 步驟 3：填進設定檔

編輯 `assets/config.js`，把 `backend` 改成 `'appsscript'` 並填入網址：

```js
backend: 'appsscript',

appsScript: {
  url: 'https://script.google.com/macros/s/AKfycbxxxxxxxxxxxxxxxxxxxx/exec',
},
```

存檔、推上 GitHub，就完成了。

第一個學生交出來之後，你的雲端硬碟裡會自動出現一個資料夾
**「錄音繳交－<試算表名稱>」**，裡面是依座號命名的錄音檔，例如
`座號07-小明_20261026-2015.webm`。試算表的 `submissions` 工作表則記錄誰交了、什麼時候交。

> **改過 `Code.gs` 之後**：要回到 **部署 → 管理部署作業 → 編輯（鉛筆）→ 版本選「新版本」→ 部署**，
> 新的程式才會生效。網址不會變。

## 三、常用設定

全部都在 `assets/config.js`：

```js
title: '英語朗讀錄音作業',                 // 頁面標題
assignmentNote: '請朗讀課本第 12 頁的對話…',  // 給學生看的作業說明
seatCount: 21,                            // 班上人數（座號 1 ~ 21）
requireName: false,                       // true = 學生要一併填姓名
deadlineNote: '',                         // 截止提示文字（純提示，不會真的鎖住）
maxRecordSeconds: 180,                    // 單次錄音上限，時間到自動停止

admin: {
  username: 'imp5477',
  password: 'imp5477',
},
```

## 四、後台功能

- **統計**：已完成 / 尚未完成 / 全班人數
- **尚未完成的座號**：一行列出，可一鍵複製（方便貼到群組催交）
- **全班進度一覽**：21 格一眼看完，綠色已交、紅色未交
- **已繳交的錄音**：按「載入並播放」直接聽，載好後可以「下載」存檔，
  也可以按「Drive ↗」在雲端硬碟裡開啟原始檔
- **匯出 CSV**：含未交的人、錄音長度與檔案位置，用 Excel 開不會亂碼
- **手動補登 / 修改**：學生裝置無法錄音時的備案（見下一節）
- **刪除**：把某個座號改回「未交」請他重錄；錄音檔會移到雲端硬碟的垃圾桶

> 後台不會一進去就下載 21 個錄音，而是你點哪一個才抓哪一個，所以開啟很快。

## 五、學生的裝置無法錄音時

極少數情況下學生的瀏覽器不支援網頁錄音（例如很舊的 iPhone、或學校電腦鎖住麥克風）。
這時學生頁會直接顯示原因並叫他找老師。你可以：

1. 請學生改用 [Vocaroo](https://vocaroo.com) 錄音，把連結用任何方式給你。
2. 在後台的「手動補登 / 修改」貼上那個連結。

Vocaroo 連結會自動整理成標準網址並內嵌播放器；其他任何 http(s) 連結也接受，
會以「開啟連結」的形式呈現。這類紀錄在清單上會標示「手動補登」。

## 六、需要注意的環境條件

- **必須是 https 的網址。** GitHub Pages 本來就是 https，沒問題；
  但如果你用檔案總管直接雙擊 `index.html`（`file://`）開啟，瀏覽器不會給麥克風權限。
- **瀏覽器**：Chrome、Edge、Firefox、Safari 的近年版本都可以。
  iPhone 需要 **iOS 14.3 以上**。
- **第一次錄音會跳出麥克風權限詢問**，要按「允許」。
  如果學生不小心按了「封鎖」，要到網址列左邊的圖示裡改回來再重新整理。
- **容量**：錄音以約 32kbps 壓縮，3 分鐘大約 700KB。
  21 人一次作業約 15MB，Google 免費的 15GB 可以放很久。

## ⚠️ 七、安全性說明（請務必了解）

這是**純靜態網站**，所以：

1. **後台帳密寫在前端程式碼裡。**
   `imp5477 / imp5477` 只能擋住隨手點進 `admin.html` 的人。
   任何人按「檢視網頁原始碼」就能看到帳密。
   （而且免費帳號的 GitHub Pages 只能用在 public repo，程式碼一定是公開的。）
2. **知道後端網址的人就能讀取全班的錄音。**
   後端網址也寫在前端程式碼裡。

對於「交朗讀作業」這種用途通常沒問題，但**請不要讓學生錄任何需要保密的內容**。
如果需要真正的權限控管，就必須改用有伺服器端驗證的架構（例如 Firebase Authentication）。

## 九、常見問題

**學生按送出後出現「連不到伺服器」**
→ 多半是 Apps Script 部署時「誰可以存取」沒選「所有人」。回到 **管理部署作業** 改好即可。

**頁面顯示「本機測試模式」的警告**
→ `assets/config.js` 的 `backend` 還是 `local`，請照第二節設定。

**改了 `Code.gs` 卻沒反應**
→ Apps Script 要重新「部署新版本」才會生效，見第二節最後的提醒。

**21 個學生同時送出會不會互相覆蓋？**
→ 不會。後端用 `LockService` 排隊處理，一次處理一筆。

**錄音檔會不會越積越多？**
→ 同一座號重新繳交時，舊的錄音檔會自動移到雲端硬碟的垃圾桶，不會一直累積。

**可以讓學生錄久一點嗎？**
→ 改 `config.js` 的 `maxRecordSeconds`。不過上傳是一次送完整個檔案，
太長（例如超過 10 分鐘）會變慢，也比較容易在網路不穩時失敗。

**後台的錄音可以一次全部下載嗎？**
→ 目前是一個一個下載。要一次全拿，最快的方法是直接去雲端硬碟那個資料夾，
整個資料夾下載成 zip。
